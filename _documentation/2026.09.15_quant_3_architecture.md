## 2. Plan 01 — market data

### The cache is the authority, and it is honest about staleness

Retrieval precedence, in `chartRepository.getChartV3`:

| Situation | Result |
| --- | --- |
| Fresh persistent entry, `cache-first` | Returned immediately, no network |
| Stale entry, network succeeds | Fresh network payload |
| Stale entry, network fails | The **stale live** payload, `cache.stale = true` |
| No entry, network fails | Sample, `source: 'sample'`, `persistent: false` |

A stale live payload beats a synthetic one because it is real data that is
merely old, and the flag lets the UI say so. **Sample payloads are never
written to the cache**, and a planted sample entry is refused on read — tested
directly, because a sample row wearing live provenance is the one failure mode
that would silently corrupt every downstream calculation.

### Integrity rules that are load-bearing

1. Payload → `*.tmp` → `fsync` → rename. The fsync is before the rename: without
   it the rename can be durable while the bytes it points at are not.
2. SHA-256 is over the **compressed** bytes, so a truncated file fails
   verification rather than gunzipping into nonsense.
3. A hash mismatch invalidates only that entry; the manifest is untouched.
4. Payload commits before the manifest. Dying between the two leaves the
   manifest pointing at the *previous* payload — the safe direction to fail.
5. Pruning sweeps orphans, because rule 4 can leave a file nothing references.
6. Cache keys are sanitised: a key is partly a user-supplied symbol, so
   traversal has to be structurally impossible rather than unlikely.

### Sessions

`marketSession.ts` is pure and uses `Intl.DateTimeFormat`, so DST comes from the
IANA database. A fixed UTC offset here is correct for half the year — the tests
assert that 10:00 ET in January and in July classify identically.

Only intraday bars get a real session. A daily bar spans whole sessions, so
calling it `regular` would be a claim the data does not support; those are
`unknown`.

`isActiveMarketState` excludes `PREPRE` and `POSTPOST`. They are the dead zones
between sessions, and the naive `startsWith('POST')` test polls all night.

## 3. Plan 02 — chart, events, signal history

### Event reaction describes, it does not explain

The output type is `ChartEventReaction`, the headline number is
`residualReturnPercent`, and the permitted copy is "Reaction", "Residual move"
and "Observed move". A macro print moves everything at once, so a raw asset
return says almost nothing about the symbol — the residual does.

Every metric is independently nullable. A missing benchmark loses the residual
but keeps the asset return; a zero baseline reports "not normalizable" rather
than dividing by zero. The benchmark is measured over the **asset's own window
timestamps**, so a differing bar grid cannot manufacture a residual.

### Signal history is append-only

`appendSignalSnapshot` returns the existing record unchanged rather than
rewriting it. A marker drawn on a 2024 bar shows what the model said in 2024.
Only the forward `outcome` block may be filled in later, because an outcome is a
fact learned afterwards rather than a revision of the original claim.

The regression test for this drives the current model to the *opposite*
conclusion on the same bar — opposite decision, opposite direction, different
setup, different geometry — and asserts the stored snapshot is untouched.

The v2 import is guarded by a `migratedFrom` marker, derives ids the same way
native records do, and invents nothing v2 lacked: `entry` and `target2` stay
`null` rather than being back-filled from today's engine.

### Markers are filtered before they are drawn

`filterToVisibleRange` → `clusterByPixelBucket` → marker models. Order matters:
clustering the full set and filtering afterwards does the expensive work on
every event in history. A 1,000-event fixture puts a few dozen markers into
lightweight-charts, which is what keeps pointer interaction responsive.

Every marker carries a glyph and an `accessibleLabel`, and in-canvas markers get
keyboard-reachable equivalents, so colour is never the only indicator.

## 4. Plan 03 — portfolio

### A missing price is not zero

This single rule shapes `portfolioAggregation.ts`. An unpriced position keeps
its quantity and cost basis, reports `null` market metrics, **leaves the weight
denominator**, and is named in `unpricedSymbols`. Valuing it at zero would
understate the portfolio and overstate every other weight.

Cash *is* in the denominator: a portfolio that is half cash genuinely has half
its value in cash, and excluding it would report every position at double its
real weight.

P/L is measured only against the cost basis of positions that could be priced.
Mixing in an unpriced position's basis would report a loss equal to its entire
cost.

### Risk

| Decision | Reason |
| --- | --- |
| Date intersection, never forward-fill | Padding injects zero returns, which drags measured volatility and correlation toward zero — it makes the portfolio look safer than it is. A test measures a sparse series and its forward-filled twin to demonstrate this. |
| Empirical VaR/CVaR | A parametric VaR on financial returns understates the tail, which is the one number nobody should understate. |
| Cash as a zero-volatility sleeve | 50% cash visibly halves volatility and beta. Renormalising the risky weights to 100% would hide that. |
| Nulls plus named exclusions | Insufficient overlap reports `null` and names the excluded symbols; over 20% of non-cash value excluded escalates to a `partial` warning. |

Component contributions sum to 100% by construction:
`Σ wᵢ(Σw)ᵢ/σ = wᵀΣw/σ = σ²/σ = σ`.

### Exposure is a floor, not a total

Quant has an ETF's *top* holdings, not a complete constituent set. So direct and
indirect exposure stay in **separate columns**, their sum is named
`combinedKnownWeightPercent`, and `coveragePercent` states how much value had
known classification. Unclassified value appears as its own slice rather than
being dropped, because a breakdown that silently omits 30% reads as complete.

Concentration is computed over direct positions only — a fund is one decision,
and exploding it into constituents would make a diversified index fund look
concentrated.

### Portfolio context never touches the signal

Two independent outputs:

```text
Instrument Decision: BUY CANDIDATE          ← signal engine, recorded as history
Portfolio Context:   Concentration exceeded ← portfolio rules, computed separately
```

A portfolio rule that could rewrite a snapshot would make the historical signal
record a function of today's holdings. The cross-plan regression test builds a
portfolio 90%+ concentrated in a symbol, takes the resulting warning, and
asserts the stored snapshot is byte-identical afterwards.

## 5. Plan 04 — discovery

### The problem being replaced

Quant 2.1 did `universe.slice(0, request.limit)` with a default near 120 and
called it "US stocks". That is the first N directory rows in alphabetical order.

Coverage is now a first-class output — universe, hydrated, scanned, eligible,
current-session, stale, failed — and the label is `Quant U.S. universe` plus the
count. Eligibility returns **every** rejection reason so the funnel explains
itself rather than leaving most of the universe unaccounted for.

### Why robust statistics

A single percent number cannot say whether +6% is remarkable: for a utility it
is enormous, for a small-cap biotech it is Tuesday. Median/MAD standardisation
answers that, and MAD is used rather than standard deviation because the
outliers being hunted would otherwise inflate the denominator meant to detect
them.

Residuals subtract `beta * benchmarkReturn`, not the raw benchmark return. On a
day the market falls 3%, a high-beta name falling 4% is unremarkable —
subtracting a fitted beta says so. Below 40 overlapping observations no
regression result is produced at all.

### Grouped and capped attention

```text
abnormalMove 0-20 · participation 0-15 · relativeStrength 0-15
structuralChange 0-15 · modelEvidence 0-15 · novelty 0-10
personalRelevance 0-10 · qualityPenalty 0-30 (subtracted)
```

`abnormalMoveScore` takes the **maximum** of its measures, not their sum: the
20-day z-score, the benchmark residual and the sector residual are three views
of one move, and adding them pays three times for one event.

`modelEvidence` is capped at 15 so a backtest cannot dominate live market
evidence, and a null expectancy CI is never read as positive. Stale data is the
heaviest penalty, because a high score computed from last week's bars *looks*
current.

The label is `Attention`, never `Confidence`. Output is a `Research Candidate`,
never a recommendation, and `whyNowReasons` are phrased as observations.

### Novelty is change, not strength

Every increase is tied to a **crossing**. A symbol that has been strong and
unchanged for three weeks scores zero — there is nothing new to look at. A first
scan reports 0 with an explanation rather than marking the whole universe novel.

### Two stages

```text
hydrated eligible universe
  ↓ Stage A: pure features, no Signal Engine replay
top 300 preliminary
  ↓ Stage B: deterministic signal core
top 50 deep → setup-specific historical replay ONLY here
  ↓
Today shortlist (≤20), grouped and deduplicated
```

Running the replay across the universe takes minutes; running it on 50 symbols
takes seconds and is where it changes a ranking. Kronos and QRM are not run at
any width here.

## 6. Plan 05 — QRM-3

### QRM is a separate model, and it is experimental

Three models coexist and are **never merged by averaging**:

| Model | Speaks in | Authority |
| --- | --- | --- |
| Signal Engine V2 + unified model | BUY / WAIT / SELL | Authoritative |
| QRM-3 | long-candidate / short-candidate / wait / unavailable | **Experimental only** |
| Kronos | "sampled median positive" | Descriptive |

`describeModelDisagreement()` surfaces a disagreement as research context. Each
keeps its native semantics; `ResearchModelView` deliberately has no shared
numeric `confidence`.

### The pipeline

```text
buildQrmStateAt(candles, spy, cutoffIndex)   point-in-time, robust, clamped ±8
  ↓
buildAnalogueRecords(...)                    horizon realised BEFORE the cutoff
  ↓
nearestAnalogues(...)                        weighted standardised distance
  ↓
solveKernelTemperature(..., targetEss)       bandwidth solved, not fixed
  ↓
directWeightedDistribution(...)              the simpler baseline to beat
  ↓
simulateQrmPaths(...)                        seeded stationary block bootstrap
  ↓
QrmForecastSnapshot                          RAW sampled quantiles
```

### The four decisions that matter

**Point-in-time everything.** A single off-by-one leaks the future into a model
that is then benchmarked as if honest. The leakage tests poison every future bar
with `1e6` — including the benchmark series — and assert the state, the analogue
set and a replayed forecast are all bit-identical.

**Analogue eligibility.** A candidate's longest horizon must have fully realised
*before* the cutoff. A 10-day analogue drawn from nine days ago is partly made
of the same future the model is predicting, and the benchmark would reward it.

**ESS-targeted bandwidth.** A fixed temperature concentrates all weight into two
or three analogues on some states and spreads it uselessly flat on others.
Targeting ESS makes the effective sample comparable across states; an
unreachable target is reported as such. Bisection is valid because ESS rises
monotonically with temperature — asserted in the tests, not assumed.

**Stationary block bootstrap.** Independent daily draws destroy volatility
clustering: real markets have quiet weeks and violent weeks, and a path
assembled from unrelated single days has neither. Continuation probability
`c = 1 − 1/L` gives an expected block length of L sessions. The generator is
seeded, so the same config produces byte-identical paths.

### The harness exists to falsify

Every experiment scores CRPS and direction Brier against three deliberately
simple baselines — zero-return, historical-unconditional, momentum-sign —
because a model never compared to a trivial competitor always looks impressive.

Forecast quality and decision quality are scored **separately**, and entry
location is measured explicitly: a well-calibrated model can still make badly
located entries, which is precisely the failure the entry-penalty metric exists
to catch.

Runtime is a **product** gate. Failing it keeps QRM in manual Lab mode; it never
justifies weakening a statistical threshold.

Running the loop on synthetic random walks reports QRM losing to the
unconditional baseline and the gates refusing promotion. That is the correct
result — a random walk has no conditional structure to find — and it is the
clearest demonstration that the harness is not rigged to pass.

## 7. Test map

| Suite | Covers |
| --- | --- |
| `test:signal-v2` | Execution simulator, causal replay, statistics (pre-existing) |
| `test:unified` | Unified signal model, Price Acceptance, indicator math, QRM decision |
| `test:market-data-v3` | Cache integrity, corruption, pruning, retrieval precedence, DST |
| `test:chart-v3` | Session quote formatter, extended-hours rules, marker models, preferences |
| `test:events-v3` | Event reaction engine; five event parsers, all offline against fixtures |
| `test:signal-history-v3` | Append-only immutability, v2 migration, viewport clustering |
| `test:portfolio-v3` | Document validation, backup recovery, aggregation, exposure, CSV |
| `test:portfolio-risk-v3` | Every risk case plan 03 enumerates, including forward-fill contrast |
| `test:discovery-v3` | Eligibility, robust features, capped attention, novelty, full run |
| `test:qrm-v3` | Leakage, reproducibility, ESS monotonicity, weighted quantiles, gates |

Two test-authoring traps were found while writing these, both of which had made
a test silently assert nothing:

1. **Separate esbuild bundles give separate module instances.** Bundling
   `chartRepository` and `marketCache` independently meant the repository read a
   different cache root than the test configured. Fixed by bundling through one
   stdin entry point; the same trap applies to any service-plus-dependency pair.
2. **`setDiscoveryHistoryRoot` takes the parent directory.** A test wrote its
   corrupt fixture one level above the real file. The store now exports
   `discoveryHistoryDir()` so callers do not have to guess.

## 9. Extending safely

- **A new chart-event source** is a parser under `src/main/services/events/`
  plus a line in `economicEvents.ts`. Parsers take a string or a decoded payload
  and return records; no parser may fetch, and every one needs a fixture test.
- **A new risk metric** goes in `portfolioRisk.ts` and must be independently
  nullable. Returning 0 for "could not measure" is the bug this module is built
  to avoid.
- **A new attention component** needs its own cap in `ATTENTION_COMPONENT_CAPS`.
  If it measures the same underlying phenomenon as an existing component, it
  belongs *inside* that component's maximum, not beside it.
- **A QRM parameter change** is a new config version: it changes
  `qrmConfigHash`, which changes the snapshot id, and it must be benchmarked
  before it is kept.
